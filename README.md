# 가족 자산 대쉬보드 — 배포 가이드 (v2)

폰·PC 어디서든 로그인해서 보는 개인용 자산 대쉬보드입니다.
거래를 입력하면 보유 종목·수익률·현금비중·규칙 위반 여부가 즉시 다시 계산됩니다.

---

## 구성 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 웹앱 본체 — 로그인, 대시보드 5탭, 거래입력, 시세, 설정 |
| `config.example.js` | Supabase 접속 정보 예시 → `config.js`로 복사해서 채움 |
| `schema.sql` | 테이블 + 뷰 + 보안(RLS). **모든 테이블에 `pf_` 접두사** |
| `seed.sql` | 현재 거래 80건 + 계좌 16개 + 종목 27개 초기 데이터 |
| `scripts/fetch_prices.py` | 지연시세 스크래퍼 (종목 목록을 DB에서 자동으로 읽음) |
| `.github/workflows/update-prices.yml` | 10분마다 자동 시세 갱신 (장중에만 실제 수집) |

---

## 선물 매매일지와의 관계

같은 Supabase 프로젝트를 쓰지만 **데이터는 완전히 분리**돼 있습니다.

| 앱 | 테이블 |
|---|---|
| 선물 매매일지 | `trades`, `bias_state` |
| 가족 대시보드 | `pf_trades`, `pf_accounts`, `pf_persons` … |

`schema.sql`은 `pf_` 로 시작하는 테이블만 건드립니다. 선물 매매일지 데이터는 안전합니다.

---

## v1에서 달라진 점

**보유 종목 테이블(`holdings`)을 없앴습니다.** 이전에는 거래내역과 보유현황이 각각 따로 저장돼서, 둘이 어긋나면 조용히 틀린 값이 표시되는 문제가 있었습니다. 이제 **보유는 거래에서만 계산**됩니다. 진실이 한 곳에만 있으니 어긋날 수가 없습니다.

**R 배수 계산이 가능해졌습니다.** `tid`(매수·매도를 한 거래로 묶는 ID), `planned_risk`(계획 리스크 금액), `seq`(같은 날짜 내 순서) 필드가 추가됐습니다. 이게 없으면 "이 거래에서 계획 대비 몇 배를 벌었나"를 계산할 수 없습니다.

**모든 테이블에 `pf_` 접두사를 붙였습니다.** 선물 매매일지 앱이 쓰는 `trades` 테이블과 이름이 겹쳐서, 예전 스키마를 실행하면 선물 기록이 삭제되는 문제가 있었습니다.

**시세 이력을 쌓습니다 (`pf_price_history`).** 스크래퍼가 실행될 때마다 종목별 당일 시가·고가·저가·종가를 기록합니다. 이걸로 MAE/MFE(진입 후 최악·최고 지점)를 계산합니다.

**시세 스크래퍼가 종목 목록을 자동으로 읽습니다.** 예전엔 파이썬 파일에 종목이 하드코딩돼 있어서 새 종목을 살 때마다 코드를 고쳐야 했습니다. 이제 앱에서 새 종목을 매수하면 자동 등록되고 스크래퍼가 알아서 가져옵니다. **환율도 함께 수집합니다.**

## 무료로 쓰는 3가지 서비스

1. **Supabase** — 로그인 + 데이터베이스
2. **Netlify** (또는 Vercel) — 웹사이트 호스팅
3. **GitHub** — 코드 저장 + 시세 자동 갱신(Actions)

계정 생성과 로그인은 보안상 본인이 직접 하셔야 합니다. 막히면 화면을 캡처해서 물어보세요.

---

## STEP 1 — Supabase 프로젝트 만들기

1. https://supabase.com 접속 → 가입
2. **New project** → 이름 아무거나, 지역은 `Northeast Asia (Seoul)` 추천, DB 비밀번호 설정
3. 좌측 **SQL Editor** → **New query**
4. `schema.sql` 내용을 **통째로** 붙여넣고 **Run**
5. 좌측 **Authentication → Sign In / Providers → Email** 이 켜져 있는지 확인
   개인용이라 **"Confirm email" 끄기**를 권장합니다 (이메일 인증 없이 바로 로그인)

---

## STEP 2 — 접속 키 확인 + config.js 만들기

1. 좌측 **Project Settings → API**
2. **Project URL** 과 **anon public** 키 복사
3. `config.example.js`를 복사해서 같은 폴더에 **`config.js`**로 저장하고 두 값을 붙여넣기
4. **service_role** 키도 따로 복사해둡니다 (STEP 5 시세 스크래퍼용)

> ⚠️ `service_role` 키는 모든 보안을 우회합니다. 웹사이트나 GitHub 공개 저장소에 절대 올리지 마세요. GitHub Secrets에만 넣습니다.

---

## STEP 3 — 계정 만들기 (중요: seed보다 먼저)

`seed.sql`은 "누구의 데이터인지"를 알아야 하므로 **계정이 먼저 있어야 합니다.**

1. `webapp` 폴더의 `index.html`을 브라우저로 열기 (아직 배포 전이어도 됩니다)
2. 이메일·비밀번호 입력 후 **회원가입** 클릭
3. 다시 **로그인**
4. 로그인이 되면 빈 대시보드가 보입니다 (데이터가 아직 없어서 정상)

---

## STEP 4 — 초기 데이터 넣기

1. Supabase 좌측 **Authentication → Users** → 방금 만든 계정 행의 **UID** 복사
   (`a1b2c3d4-...` 형태의 긴 문자열)
2. `seed.sql`을 열어서 맨 위의 `YOUR-UUID-HERE`를 그 UID로 바꾸기

   ```sql
   insert into _owner values ('a1b2c3d4-5e6f-7890-abcd-ef1234567890');
   ```

3. **SQL Editor → New query**에 `seed.sql` 전체를 붙여넣고 **Run**
4. 앱을 새로고침하면 거래 80건과 모든 계좌가 보입니다

> **왜 UID를 직접 넣나요?** SQL Editor는 관리자 권한으로 실행돼서 `auth.uid()`가 비어 있습니다. 그래서 대상을 명시해야 합니다. 앱 안에서 하는 작업은 이 과정이 필요 없습니다.

---

## STEP 5 — 웹사이트 배포 (Netlify)

정적 사이트라 빌드 설정이 필요 없습니다.

### 방법 A — 드래그 앤 드롭 (가장 간단)

1. https://app.netlify.com 가입
2. **Sites** → **"Deploy manually / Drag and drop"** 영역에 `webapp` 폴더를 통째로 끌어다 놓기
   (`config.js`를 채운 상태여야 합니다)
3. `https://랜덤이름.netlify.app` 주소 생성 → 폰에서도 접속 가능
4. **Site configuration → Change site name**에서 주소 변경 가능

### 방법 B — GitHub 연동 (자동 배포 + 시세 자동갱신)

1. GitHub에 저장소 생성 (**Private 권장**)
2. `webapp` 폴더 내용을 push
   - ⚠️ `config.js`는 anon 키라 공개돼도 RLS가 막아주지만, 저장소는 Private을 권장합니다
3. Netlify → **Add new site → Import an existing project** → 저장소 선택
4. 빌드 명령 비워두고 배포 → 이후 push할 때마다 자동 반영

---

## STEP 6 — 시세 자동 갱신 (GitHub Actions)

방법 B로 GitHub에 올렸다면 시세가 자동으로 갱신됩니다.

저장소 → **Settings → Secrets and variables → Actions → New repository secret** 으로 3개 등록:

| 이름 | 값 |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_SERVICE_KEY` | service_role 키 |
| `SUPABASE_OWNER_UID` | STEP 4에서 복사한 본인 UID |

선택 (국내 실시간 시세를 원할 때):

| 이름 | 값 |
|---|---|
| `KIWOOM_APP_KEY` | 키움 REST API 앱키 |
| `KIWOOM_APP_SECRET` | 키움 시크릿 |
| `KIWOOM_ENV` | `real` 또는 `mock` |

등록 후 **Actions 탭 → 시세 자동 갱신 → Run workflow**로 수동 실행해서 확인해보세요.

## 시세는 실시간이 아닙니다

지연이 두 겹으로 쌓입니다.

| 층위 | 지연 | 이유 |
|---|---|---|
| 데이터 소스 | 15~20분 | 무료 소스(alphasquare·Google Finance)가 원래 지연 데이터 |
| 수집 주기 | 최대 10분 | GitHub Actions cron |
| **합계** | **보통 15~25분** | |

**스윙 트레이딩에는 충분합니다.** 며칠~몇 주 보유하고, 이 대시보드는 "지금 내 자산이 얼마인가"를 보는 용도이기 때문입니다.

**다만 손절 감시는 여기에 의존하면 안 됩니다.** 15분 늦게 알게 됩니다. 손절은 증권사 앱의 자동 손절(STOP) 주문으로 걸어두세요.

국내 실시간이 필요하면 키움/KIS API 키를 Secrets에 넣으면 됩니다(무료). 미국주식 실시간은 거래소 라이선스라 유료입니다.

## 사용법

### 대시보드 5개 탭

**개요** — 총자산, 원금대비 수익률, 보유 수익률, 현금 비중, 거래당 기대값. 주식/현금·섹터 도넛 차트.

**계좌** — 계좌별 보유 종목, 평균단가, 현재가, 비중, 손익률.

**규칙 감시** — 설정한 규칙을 자동으로 검사합니다.
- 동시 보유 개수 초과
- 단일종목 비중 초과
- 총 오픈 리스크 초과
- **손절선까지 거리** (가까운 순 정렬) — 손절가를 입력하지 않은 종목은 평균단가 −10%로 추정하고 "추정"으로 표시
- 손절선을 이미 하회한 종목은 상단에 경고 배너

**성과·R** — 매매 복기의 핵심 화면입니다.

- **누적 R 곡선 + 드로다운 차트** — 시간순 자산 곡선과 고점 대비 낙폭을 함께 표시
- 승률, 총 R, 거래당 기대값, 평균 승R/패R, 손익분기 승률
- 승률 95% 신뢰구간 — 표본이 적으면 지금 숫자가 운일 수 있음을 보여줍니다
- **최대 드로다운**, **최대 연승/연패**
- **평균 보유기간** (이긴 거래 vs 진 거래 분리)
- **평균 MAE / MFE** — 진입 후 얼마나 역행했다가, 얼마나 순행했는지
- R 분포 히스토그램
- **전략별 / 심리별 성과 표** — 어떤 셋업과 어떤 감정 상태가 실제로 돈이 되는지
- **기대값 시뮬레이터** — 승률·승R·패R을 조절하며 흑자 전환 조건 탐색
- 청산 사유 분포, 청산 거래 목록 (보유일·MAE/MFE 포함)

**세금** — 사람별 해외/국내 실현손익 분리, 올해 남은 무세 한도, 예상 양도소득세.

### 거래 입력

계좌·구분·종목·수량·단가만 넣으면 됩니다. 나머지는 선택입니다.

- **전략·심리는 필수입니다.** 비워두면 저장되지 않습니다. 나중에 "어떤 방식이 돈이 되는지"를 분석하려면 반드시 필요합니다. 솔직하게 고르세요 — 감으로 샀으면 `감매매`, 남들 사길래 샀으면 `FOMO매매`입니다. 전부 `테마모멘텀매매/확신`으로 찍으면 분석이 무의미해집니다.
- **매도할 때는 청산사유도 필수입니다.** 계획대로 나왔는지(`손절가도달`·`목표가도달`) 감정으로 나왔는지(`감정적조기청산`)가 시스템 개선의 핵심 데이터입니다.
- **손절가를 넣으면** 계획 리스크가 자동 계산되고 R 배수를 구할 수 있습니다. 넣지 않으면 그 거래는 R 통계에서 빠집니다.
- **USD 종목의 손절가는 달러로 입력하세요.** 원화로 넣으면 비교가 어긋납니다.
- **거래ID(`tid`)** 는 비워두면 자동 생성됩니다. 같은 종목을 나눠 사거나(분할매수) 나눠 팔 때는 **같은 ID를 직접 입력**하세요. 그래야 하나의 거래로 묶여서 평균단가와 R이 제대로 계산됩니다.
- **매도**를 선택하면 청산사유 항목이 나타납니다. "감정적조기청산"이 쌓이면 성과 탭에서 경고로 표시됩니다.
- 새 종목은 자동으로 등록되며 섹터는 "기타"로 들어갑니다. 시세 탭이나 Supabase에서 고칠 수 있습니다.

### 시세

보유 중인 종목만 표시됩니다. 스크래퍼가 자동 갱신하지만 직접 고칠 수도 있습니다(출처가 `manual`로 바뀝니다).

### 설정

사람별 원금(수익률 기준액)과 운용 규칙(거래당 리스크, 손절폭, 동시 보유 상한 등)을 바꿀 수 있습니다.

## 계산 방식

**보유 수량과 평균단가** — 이동평균법입니다. 매수하면 원가에 더하고, 매도하면 평균단가만큼 비례해서 뺍니다. **전량 매도해서 수량이 0이 되면 원가도 0으로 리셋**되므로, 나중에 다시 사면 새 평균으로 시작합니다.

**보유 수익률** — 지금 들고 있는 종목의 미실현 손익률입니다.

```
(보유 종목 평가액 − 그 종목들의 매수원가) ÷ 매수원가
```

이미 판 종목의 손익(실현손익)은 들어가지 않습니다. 연초 대비(YTD)와도 다릅니다 — 기간 개념이 없고, 오직 "지금 보유분이 얼마나 올랐나"만 봅니다.

**원금대비 수익률** — (현재 총자산 − 설정한 원금) ÷ 원금. 실현·미실현·현금이 모두 반영된 전체 성적표입니다.

두 지표가 크게 다르면 그 차이가 **과거 실현손익**입니다. 예를 들어 원금대비 −35%인데 보유 수익률이 +5%라면, 지금 종목은 잘 가고 있지만 과거에 판 종목에서 손실이 컸다는 뜻입니다.

**R 배수** — 실현손익 ÷ 계획 리스크 금액. 같은 `tid`의 매수·매도를 묶어서 계산합니다. 부분 매도면 매도한 비율만큼만 계산합니다.

**기대값** — (승률 × 평균 승R) − (패률 × 평균 패R). 이 값이 양수여야 거래를 반복할수록 자산이 늘어납니다.

**드로다운** — 누적 R의 고점 대비 현재 낙폭. 규칙의 `-15% 중단선`을 실제로 감시하는 지표입니다.

**MAE / MFE** — 보유 기간 중 평균 진입가 대비 최저점(MAE)과 최고점(MFE). MAE가 손절폭보다 훨씬 얕으면 손절이 너무 넓은 것이고, MFE가 실제 청산 수익률보다 훨씬 높으면 익절이 너무 이른 것입니다. `pf_price_history`에 이력이 쌓여야 표시됩니다.

## 문제 해결

**로그인이 안 됩니다**
Authentication → Providers → Email이 켜져 있는지, "Confirm email"이 켜져 있다면 메일함을 확인하세요.

**로그인은 되는데 데이터가 안 보입니다**
STEP 4의 UID가 실제 로그인 계정과 일치하는지 확인하세요. 다른 계정으로 회원가입했다면 그 계정의 UID로 seed를 다시 실행해야 합니다.

**seed.sql 실행 시 오류가 납니다**
`YOUR-UUID-HERE`를 실제 UID로 바꿨는지 확인하세요. 따옴표는 남겨두어야 합니다.

**시세가 갱신되지 않습니다**
Actions 탭에서 로그를 확인하세요. Secrets 3개가 모두 등록됐는지, 특히 `SUPABASE_OWNER_UID`가 있는지 확인하세요. 장이 닫혀 있으면 수집을 건너뜁니다(정상).

**"미보유 종목 매도" 경고가 뜹니다**
매도가 매수보다 먼저 처리된 경우입니다. 같은 날짜라면 입력 순서(`seq`)를 확인하세요. 매수를 먼저 입력해야 합니다.

**규칙 감시에서 "추정"으로 표시됩니다**
그 종목의 매수 거래에 손절가를 입력하지 않아서입니다. 정확한 감시를 원하면 손절가를 넣어 다시 입력하세요.

**MAE/MFE가 전부 "-"로 나옵니다**
`pf_price_history`에 아직 데이터가 없어서입니다. 스크래퍼가 며칠 돌면서 이력이 쌓이면 표시됩니다. 과거 거래는 소급 계산되지 않습니다.

**전략별 성과에 "태그가 한 종류뿐" 경고가 뜹니다**
모든 거래를 같은 전략으로 기록해서입니다. 실제 셋업에 맞게 구분해서 넣어야 비교가 됩니다.

**선물 매매일지 데이터가 걱정됩니다**
`schema.sql`과 `seed.sql` 모두 `pf_` 로 시작하는 테이블만 건드립니다. 실행 전에 확인하려면 SQL Editor에서 `select count(*) from trades;` 를 돌려 건수를 적어두고, 실행 후 다시 돌려 같은지 확인하세요.
